# AI Tech Report

产出有来源、有取舍、有分析的中文 AI 行业周报。开始前读取 `AGENTS.md`、`sources.yml` 和上一期周报的“速览”；内容红线与发布权限以 `AGENTS.md` 为准。

## 确定范围

- 运行 `python3 scripts/build.py --current-week`，以 `Asia/Shanghai` 的 ISO 周确定周一至周日和本次收集截止时间。普通生成只处理当前周；仅在用户明确要求时处理历史周，报告不标记补写状态。
- 普通生成每次从本周周一重新扫描到运行时，历史周则扫描该周周一至周日；不只补上次运行后的信息，也不因断更扩大窗口。尚未发生的进展不得写成事实；正文注明统计周期。
- 若本周报告已存在，读取其“速览”和“其他动态”（旧稿称“简讯”）及必要正文，重新核实后更新同一文件，不因去重丢失仍相关的已收录事件。
- 跨周去重只参考上期“速览”；疑似旧闻延续再读对应正文，只有本周出现实质新增才续写。

## 发现与筛选

固定信源和开放检索都要执行：

1. 逐项访问 `sources.yml` 的全部入口，记录实际结果。访问失败最多重试一次；仍失败则记录缺口，不能当作无新增。
2. 开放检索分两轮：
   - 首轮在模型、应用与 Agent、基础设施、产业与政策四个方向，用不限厂商和站点的中英文关键词广泛发现，并查看国内外科技媒体、垂直媒体和热点榜单。
   - 次轮按候选分布补查遗漏的子领域、地区或主体；结果过度集中或重复旧闻时继续针对性补查。
   - 每个方向两轮各至少一组独立检索，覆盖中国生态及至少两个地区的政策动态。使用日期过滤或明确起止日期，不用“本周”“最近”等相对时间词界定窗口。

列表、榜单和搜索摘要只作发现入口。初筛确认标题、时间和核心变化；列表未覆盖完整窗口时补查日期范围或分页，仍有缺口则如实记录。不要把页面或模型文件的更新时间直接当作事件发布日期。

按 [底稿模板](assets/research-template.md) 创建 `research/YYYY-Www.md`，记录每个固定入口、每组检索、候选取舍及核心事实证据。

- 同一事件合并为一个候选；区分来源发布时间、事件发生时间和本周新增点，不凭文章日期推断事件日期。只有窗口内有实质新增的事件才可入选。
- 按证据强度、变化幅度、影响范围与关注度线索筛选；热度和转载量不能代替影响力。按价值决定重点事件和“其他动态”的数量，素材不足时宁缺毋滥。
- 固定入口已尝试、两轮检索完成、候选去重且足以支持成稿时停止扩展搜索。

## 核实与撰写

- 入选事件逐条访问直接支持事实的官方发布、论文、项目仓库或可靠报道，记录“核心事实 → 本次访问的链接”及数字的适用条件和来源性质。发现页不能代替原文；厂商自述与未经独立验证的指标须明确标注。
- 融资金额、性能优势、事故归因、争议性指控等关键陈述应寻找独立佐证；多篇转载同一消息不算独立验证。无法核实的关键断言应删除，必要时放弃事件。来源访问失败最多重试一次，再换可靠来源或放弃。
- 以 [报告模板](assets/report-template.md) 撰写 `content/weekly/YYYY-Www.md`。“速览”与重点事件标题按顺序一一对应；重点正文交代变化、证据、限制与判断。观点和事实分开，单个事件的判断放在对应正文后的引用块，跨事件判断放在开篇。
- “其他动态”通常每条 1–2 句，必要时补充数字条件或来源性质；需要较长分析时改为重点或删去次要细节。
- 面向读者陈述具体事实和判断，不写解释写作过程的套话；“后续观察”只保留明确可跟踪的事件、指标或制度进展。

## 复核与交付

- 构建前对照底稿逐条检查窗口归属、直接证据、厂商自述标注和事件去重。构建脚本不能判断来源是否支持陈述，须重读入选来源。
- 同周重跑可以复用尚未清理的底稿作线索，但引用必须在本次重新访问；底稿已清理时从本期报告恢复已收录事件。
- 运行 `python3 scripts/build.py`，确认 `site/weekly/<周编号>/index.html` 存在。完成事实复核与构建后删除本次底稿。
- 扫描缺口在交付时说明，不在正文末尾附通用“覆盖说明”。向用户报告周报路径、收集窗口、核心内容和验证结果。
- 默认到此结束。只有明确要求提交或发布时才创建 commit；只有明确要求 push 或发布时才 push，遵循 `AGENTS.md` 的发布规则。
